## لماذا مشروعان؟
- ARBNT: تطبيق مجتمع بصفحات حسابات/منشورات/ردود/مجتمعات وإدارة عاملة في PHP Native + JSON.
- ONE Engine: نواة عامة لإنشاء وإدارة مواقع مستقلة واختيار نمط Static/Hybrid/Dynamic. في v0.1/v0.2 المبكرة، ليست CMS كاملة.
- **الهدف:** الاستفادة من ARBNT مع الاحتفاظ بأمان ONE Engine واستقلال كل موقع، لا استنساخ مجتمع آخر مستقل.

## قرارات معمارية غير قابلة للتجاهل
1. Hybrid Headless: PHP Native/HTML افتراضي، REST/JSON اختياري؛ لا Node/Composer/framework أو GraphQL إجباري.
2. Core: كائنات، علاقات، قدرات، صلاحيات؛ **الصلاحيات أولاً**، deny by default، explicit deny يسبق allow، عزل الموقع والمالك ليس إذنًا ضمنيًا.
3. Storage: ملفات JSON خاصة افتراضيًا؛ SQLite فقط بعد تفعيل صريح (constructor ينشئ الملف!)، MariaDB/PDO خيار لاحق. لا تنسخ بيانات مستخدمين أو أسرار.
4. Delivery: مواقع مستقلة عن المركز، Static/Hybrid/Dynamic. Runtime لا يستدعي Builder أو CentralManagement.
5. Builder: whitelist لملفات الحزمة وstaging وmanifest/version وrollback، لا إدراج أسرار ولا تخزين خاص.
6. CMS: إنشاء القسم والصفحة والرابط من الإدارة مع شكل وقالب وموضع (navbar/sidebar/footer) وحق ظهور منفصل لكل عنصر/بلوك/إجراء.
7. واجهة: RTL عربية متجاوبة، تصميم ARBNT السليم مصدر إلهام وإعادة استخدام مع مراجعة، قائمة للهاتف، وضع ليلي اختياري. لا تملأ الواجهة بأزرار غير عاملة.
8. SEO: canonical من إعداد النطاق، robots/sitemap حسب الموقع والصفحات العامة، noindex للمعاينة، وعدم تخزين خاص في كاش عام.
9. الأمن: جلسات/هويات/CSRF/rate limit/إخراج مهرب، خصوصية، صيانة تزامن JSON، ملفات خارج public، صلاحيات على الخادم.
10. اختبار كل مرحلة: PHP 8.3/8.4 وlint وHTTP والصلاحيات والعزل والتزامن والهواتف؛ اختبار CI لا يكفي وحده لإثبات جودة تجربة المستخدم.

## جرد ARBNT المتحقق مبدئيًا — يحتاج مراجعة داخل الملفات قبل النقل
- العرض: `index.html`، `community.html`، `admin.html`، `assets/shell.css`، `assets/shell.js`، `assets/layout.css`، `assets/admin.css`، `assets/admin.js`.
- الحسابات: `login.html`، `register.html`، `forgot.html`، `profile.html`، `assets/auth-pages.js`، `api/community.php`.
- المحتوى: `publish.html`، `post.html`، `communities.html`، `assets/community.js`، `assets/publish.js`، `assets/communities.js`.
- التخزين: `app/core.php` وبيانات JSON محلية في ARBNT. **لا تستخدم `arbnt_read`/write مباشرة في نواة ONE Engine**؛ فرّق بين منطق البيانات وبروتوكول التخزين.
- لاحظ تعارضًا توثيقيًا في ARBNT: `AGENTS.md` و`docs/ARCHITECTURE.md` يقولان Documentation only، لكن README والكود يبينان نظام مجتمع منفذ. افحص الواقع بدل الاعتماد على عبارة واحدة.
- **مهم:** `shell.js` خاص بمسارات وAPI ARBNT؛ لا تنسخه كما هو إلى ONE Engine. استخرج تصميم الهيدر والقائمة/الهاتف ثم أعد ربط الأحداث بمسارات المحرك.

## مراحل v0.2 بالتسلسل
- **A: واجهة مشتركة قابلة للمقارنة**: إعادة استخدام نمط ARBNT للهيدر/القائمة/RTL والوضع الليلي في صفحات ONE Engine العامة، دون اعتماد مساراته أو حساباته. اختبار المتصفح والهاتف.
- **B: مراجعة الحسابات ثم نقلها**: اقرأ [تقرير المراجعة الأولية للحسابات](ARBNT_AUTH_REVIEW.md)، ثم دقّق في جلسات ARBNT وتخزين hashes وCSRF ومعدلات الطلبات ثم تكييف وحدة هوية ONE Engine؛ لا تُظهر دخولًا وهميًا.
- **C: صلاحيات عامة**: مجموعات/أدوار/منح للكائنات/الإجراءات/القوالب دون تجاوز نواة Permissions.
- **D: إدارة محتوى حقيقية**: قسم → صفحة → منشور → عرض، مع روابط/بلوكات ذات صلاحيات، ومراجعة الفصل بين خاص/عام، وعدم إدخال محرر كتابة قبل تأمين الهوية.
- **E: نشر واختبار**: استكمال تصدير الصفحات العامة وsitemap وتوافق الإصدارات ومعاينة قابلة للتجربة ومقارنة فعلية مع ARBNT.
- لكل خطوة PR صغير وCI ودليل تشغيل مرئي؛ لا تقفز إلى لوحة مركزية أو حجوزات ومراسلات ومتاجر قبل إكمال المقطع الأول.

## ما لم يتم
- الحسابات والجلسات/تسجيل الدخول من ARBNT غير منقولة حتى الآن.
- لا لوحة بناء أو تحرير عبر المتصفح؛ إنشاء صفحات CLI فقط.
- لا إدارة مركزية حقيقية أو نقل بيانات المستخدمين أو MariaDB أو نشر VPS.
- لم تُنقل كل CSS/JS من ARBNT، ولم تُستنسخ واجهته كاملة.
- ليس معنى الدمج أن النظام جاهز للإنتاج.
