# ONE Engine v0.2 — مراجعة نقل هوية ARBNT (قراءة فقط)
**نقطة الاستئناف:** ONE-V02-004 · **تاريخ الفحص:** 2026-11-11

## ما تم فحصه في `abud3d/arbnt`
- `api/community.php` الأسطر 1–27، 100–141، 242–290 (جلسات، CSRF، تفويض، تسجيل، دخول).
- `app/core.php` (مسارات التخزين وقراءة/كتابة JSON).
- `assets/auth-pages.js` و`assets/admin.js` والصفحات المرتبطة.
- **هذا فحص نقل أولي، وليس تدقيقًا شاملًا للثغرات. لم يُنقل هذا الكود بعد.**

## الأجزاء القابلة لإعادة الاستخدام *بعد التكييف*
1. `password_hash(PASSWORD_DEFAULT)` و`password_verify` لتخزين وفحص كلمات المرور.
2. `session_regenerate_id(true)` بعد الدخول، و`use_strict_mode` و`cookie_httponly` وSameSite=Lax.
3. التحقق من حظر الحساب وتفعيل البريد و`session_version` عند قراءة الجلسة.
4. `X-CSRF-Token` مع `hash_equals` وإجراء فحص origin؛ معدلات طلبات `throttle` قبل التسجيل والدخول.
5. بيانات الواجهة/نماذج تسجيل الدخول والتسجيل يمكن الاستفادة منها لكن يجب تعديل المسارات والهوية.

## عوائق قبل النقل
- `cookie_secure` غير معين صراحة في استدعاء `session_start` المعروض؛ تحقق من PHP ini والوكيل العكسي واضبط Secure عند HTTPS على تشغيل ONE Engine.
- هوية الجلسة وCSRF وأدوار `admin/member` في ARBNT محددة لموقع واحد؛ يجب تحويلها إلى سياق `siteId` و`PermissionEngine`، وعدم جعل admin العام إذنًا على كل المواقع.
- دوال ARBNT العامة و`api/community.php` تجمع التحكم بالمحتوى والمستخدمين والبريد في ملف كبير؛ لا تنسخ الملف إلى Runtime. قسّمه إلى خدمات صغيرة بعد تحديد حدود صلاحياتها.
- ARBNT يستعمل JSON ومخطط بيانات مختلفًا؛ اطلب موافقة منفصلة قبل استيراد حسابات إنتاج، ولا تحاول فتح hashes أو نسخ ملفات مستخدمين إلى مستودع التطوير.
- يجب اختبار `Origin` وCSRF للتغييرات، توجيهات إعادة تعيين كلمات المرور، قيود المعدلات، انتهاء الجلسة، وجود حساب محظور، بقاء الجلسة بعد تغيير كلمة المرور، والتزامن في التسجيل.
- اختبر الصلاحيات الإدارية من الخادم، وليس فقط من عناصر الواجهة المخفية. `role=admin` من نظام قديم لا يعادل صلاحية `siteId` في المحرك.

## المهمة التالية القابلة للاختبار
1. إنشاء وحدة `Identity` مع مخطط بيانات إصدار أول مستقل، تخزين خاص ومحوّل JSON محدد الموقع، واختبارات CSRF/join/ban.
2. نقل وظيفة *الدخول مع جلسة آمنة* ثم صفحة دخول فعلية وربطها بالموقع؛ لا تنقل لوحة الإدارة قبل اكتمال صلاحياتها.
3. اختبار PHP 8.3/8.4 ووظائف المستخدم/الزائر/الحظر/التبديل بين موقعين، وPR منفصل.
4. لا تنقل SMTP أو البيانات الموجودة من arbnt في هذا PR.

**القرار:** احتفظ بوظائف ARBNT الناجحة لكن لا تنسخ التطبيق بحالته الحالية إلى ONE Engine دون تكييف وتدقيق.
