# مراجعة المصدر arbnt

**تاريخ المراجعة: 2026-11-11.** المصدر:
[`abud3d/arbnt@1b5c44b21bc328fef7bc4645ce3140dba0ed13d1`](https://github.com/abud3d/arbnt/tree/1b5c44b21bc328fef7bc4645ce3140dba0ed13d1)،
و`VERSION` يذكر `0.6.8`.

شملت المراجعة جرد الملفات المتتبعة الـ48، ومسارات PHP الستة، وسلوك واجهات
JavaScript، وبنية صفحات HTML ومراجعها، وطبقات CSS، والوثائق ومسارات Actions.
الفحص هنا مراجعة مصدر واختبارات محلية معزولة؛ ليس اختبار اختراق لخادم الإنتاج
ولا إثباتًا لعمل البريد أو إعدادات الاستضافة. لم يُفتح VPS أو تُقرأ بيانات إنتاج،
ولم يُعدّل المستودع المصدر. الجرد الكامل في [SOURCE_INVENTORY.md](SOURCE_INVENTORY.md).

يوجد مسار API لترحيل التخزين مع كلمة مرور المدير والتحقق من SHA-256، لكن لوحة
الإدارة الحالية لا تعرض أداة الترحيل الموصوفة في بعض الوثائق؛ لا يكفي وجود
المسار الخلفي لاعتباره تدفقًا متكاملًا في الواجهة.

## التخزين والحسابات بالتحديد

`api/community.php` يجمع التوجيه والتفويض والبريد والتخزين وأعمال الحسابات
والمحتوى في ملف واحد من 469 سطرًا مكثفًا. `app/core.php` يحتوي وظائف عامة
تعتمد على ثوابت ومسارات عالمية. هوية الجلسة يعاد التحقق منها من users عند
الطلب. التحقق من تفرد اسم المستخدم والبريد يتكرر داخل قفل الكتابة، وهو إجراء
صحيح يجب الحفاظ على دلالته في الترحيل.

القراءة العامة للمنشورات والمجتمعات والملفات الشخصية لا تتضمن سياسة خصوصية
للكائن؛ جميعها مصممة لمجتمع عام واحد. الأدوار اثنان فقط، والتفويض الإداري
يعتمد مباشرة على `role === admin`. لا يوجد تنفيذ عام للموديل الموحد الذي
تصفه وثيقة المعمارية القديمة.

القديم إلى واجهة جديدة.

## القوالب والتصميم والتكرار

- HTML عربي/إنجليزي مع RTL/LTR، وتصميم فاتح/داكن وواجهات متجاوبة. معظم المحتوى
  الديناميكي يستخدم `textContent`، وهي دلالة آمنة قابلة لإعادة الاستخدام.
- الهوية والروابط والنصوص واسم النطاق وأسماء classes مرتبطة بـARBNT. لا يوجد
  سجل قوالب أو محرر blocks أو عقد theme مستقل؛ `starter/` مزيج نماذج وتحويلات.
- `community.js` و`post.js` و`profile.js` تكرر api/CSRF وحساب الوقت وقوائم
  التعديل/الحذف/البلاغ والعرض المتفرع للردود. `favorites.js` يعيد بناء بطاقات
  مشابهة. يجدر تجميع العقود والخدمات قبل ترحيل أي واجهة.
- طبقات CSS متعددة تعيد تعريف selectors مثل `.page-head` و`.post-image-thumb`
  و`.search`. بعضها تعديلات responsive مشروعة، وبعضها تراكم override؛ يحتاج
  فصل tokens والتخطيط والمكونات، وليس حذف التكرار آليًا.
- صفحات المحتوى تعتمد JavaScript للعرض ولا تولد SEO خاصًا بكل منشور من الخادم.
  ONE Engine يبدأ بعرض HTML وإعداد SEO مستقل للموقع.

مسارات Actions الخمسة هي فحوص صياغة/ملفات/توثيق. لا توجد مجموعة اختبارات
تثبت منع IDOR/CSRF، أو عزل المستخدمين، أو تزامن JSON، أو انتهاء رموز الاستعادة،
أو سلامة التثبيت. تكرار فحص الصياغة بين workflows لا يعوض هذه الفجوة.
لم تُشغّل Actions على arbnt أو يُدفع إليه أي commit.

## التصنيف

1. **قابل لإعادة الاستخدام:** مبادئ password hashing، رموز عشوائية محفوظة hashed،
   تدوير الجلسة، CSRF والمقارنة الثابتة الزمن، output escaping، قفل ثابت وrename،
   وفحوص syntax. إعادة الاستخدام هنا للعقد/الفكرة الآمنة؛ لا نقل حرفي للملفات.
2. **يحتاج تحسينًا وتنظيمًا:** تخزين JSON، الحسابات، المنشورات والردود والمجتمعات،
   المفضلة والبلاغات، الخدمات الإدارية، RTL وتخطيط المكونات. تفصل كوحدات مع اختبارات.
3. **خاص بـarbnt:** العلامة والواجهة التعريفية والنصوص والروابط وألوان الثيم
   وقوالب المجتمع وstarter ووثائق الاستضافة الخاصة به؛ تبقى هناك.
4. **غير مناسب للمعمارية:** dispatcher العملاق، globals/pointers المنفذة كـPHP،
   التخزين العام الاحتياطي، المثبت/الاستعادة العامة، اقتران admin بالمحتوى،
   وAPI القراءة القديم. تُستبدل ولا تُنقل.
